# Definition of Done

**Purpose**: Quality gate for completed work. All items must satisfy these criteria before being marked ✅ Done.

**Related**: [Documentation-Code Consistency Process](../processes/doc-code-consistency-process.md), [Acceptance Criteria for Project Naming Conventions](acceptance-criteria-for-project-naming-conventions.md)

---

## Per-Item Criteria

### User Stories & Defects

- [ ] Acceptance criteria met
- [ ] Code changes implemented and tested
- [ ] Unit tests added/updated (where applicable)
- [ ] Documentation updated (README, process docs, specification)
- [ ] No new linter errors introduced
- [ ] Backlog item status updated to ✅ Done
- [ ] RELEASE_NOTES.md updated (see [release-notes-process.md](../processes/release-notes-process.md))

### Sprint Completion

- [ ] All sprint stories completed or moved to backlog
- [ ] Sprint review notes filled in
- [ ] Sprint retrospective completed
- [ ] Product backlog updated
- [ ] **Documentation-Code Consistency Check** run this sprint (or since last sprint); no unresolved high-priority contradictions. See [doc-code-consistency-process.md](../processes/doc-code-consistency-process.md). Run before sprint planning (required) and on-demand (e.g. before major release).
