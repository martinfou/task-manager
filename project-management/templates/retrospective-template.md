# Sprint Retrospective Output Template

**Purpose**: Structured output format for sprint retrospectives. Use this template to capture retrospective improvements and process changes in a consistent, trackable way.

**Related**: [Sprint Retrospective Process](../processes/sprint-retrospective-process.md), [Backlog Management Process](../processes/backlog-management-process.md)

---

## Retrospective Output Format

After each sprint retrospective, fill in this structure and add it to the sprint document's "Sprint Retrospective Notes" section.

### What Went Well

- [Item 1]
- [Item 2]
- [Item 3]

### What Could Be Improved

- [Item 1]
- [Item 2]
- [Item 3]

### Retrospective Improvements

| ID | Description | Owner | Due Sprint | Status |
|----|-------------|-------|------------|--------|
| RI-001 | [Retrospective improvement description] | [Name] | Sprint [X] | ⭕ To Do |
| RI-002 | [Retrospective improvement description] | [Name] | Sprint [X] | ⭕ To Do |

**Status**: ⭕ To Do | ⏳ In Progress | ✅ Done

**Tracking**: Save each retrospective improvement to `backlog/retrospective-improvements/RI-XXX-description.md` using the [Retrospective Improvement Template](retrospective-improvement-template.md) and add to product backlog Retrospective Improvements section.

### Process Changes to Document

- [ ] [Process change 1] — Update [document path]
- [ ] [Process change 2] — Update [document path]

### Follow-up

- [ ] Add retrospective improvements to next sprint planning if applicable
- [ ] Update process docs per "Process Changes to Document"
- [ ] Review retrospective improvements from previous retro; close or carry forward

---

## Example

### What Went Well

- Clear sprint goal kept team focused
- Daily standups helped surface blockers early
- Pair programming on complex tasks improved quality

### What Could Be Improved

- Some stories were too large; need to break down earlier
- Documentation lagged behind code changes

### Retrospective Improvements

| ID | Description | Owner | Due Sprint | Status |
|----|-------------|-------|------------|--------|
| RI-001 | Add Definition of Ready checklist to refinement | Product Owner | Sprint 2 | ⭕ To Do |
| RI-002 | Run Documentation-Code Consistency Check mid-sprint, not just at end | Dev Team | Sprint 2 | ⭕ To Do |

### Process Changes to Document

- [ ] Add DoR to backlog-management-process.md
- [ ] Update doc-code-consistency-process.md with mid-sprint option
