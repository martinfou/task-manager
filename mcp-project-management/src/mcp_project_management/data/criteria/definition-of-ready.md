# Definition of Ready

**Purpose**: Quality gate before backlog items enter a sprint. Items must satisfy these criteria before being selected for sprint planning.

**Related**: [Definition of Done](definition-of-done.md), [Backlog Management Process](../processes/backlog-management-process.md), [Acceptance Criteria for Project Naming Conventions](acceptance-criteria-for-project-naming-conventions.md)

---

## Per-Item Criteria

A backlog item is **Ready** when:

- [ ] **Acceptance criteria** are specific and testable
- [ ] **Dependencies** are identified and resolved (or included in the same sprint)
- [ ] **Story points** are estimated (Fibonacci: 1, 2, 3, 5, 8, 13)
- [ ] **No open clarifying questions** — all ambiguities resolved
- [ ] **Technical references** included (where applicable)
- [ ] **User story** follows "As a... I want... So that..." format (for features)
- [ ] **Priority** is assigned (🔴 Critical / 🟠 High / 🟡 Medium / 🟢 Low)

---

## When to Apply

- **Before sprint planning**: Only items that meet Definition of Ready should be considered for selection
- **During backlog refinement**: Use this checklist to prepare items for upcoming sprints

---

## Exceptions

- **Critical defects** may bypass some criteria (e.g., story points) if immediate action is required
- **Spike or research items** may have looser acceptance criteria; document the outcome instead
